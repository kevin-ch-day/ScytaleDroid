## Primary Source Review

### Isolation Forest

Scikit-learn documents `IsolationForest` as an ensemble method for anomaly
detection where `score_samples` returns anomaly scores and lower values are more
abnormal. The current ScytaleDroid RDI package does not directly infer from raw
`score_samples`; it uses persisted per-window `is_anomalous` flags and
thresholds generated by the locked ML scoring pipeline.

Source: https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.IsolationForest.html

Implication: the paper must state the thresholding policy and score direction
used by ScytaleDroid, not assume a generic Isolation Forest interpretation.
Independent validation must eventually verify score direction and threshold
construction from model manifests or retraining.

### One-Class SVM

Scikit-learn documents `OneClassSVM` as unsupervised outlier detection that
estimates support of a distribution. It is sensitive to kernel/gamma/nu choices
and remains secondary in this package because baseline calibration warnings are
present.

Source: https://scikit-learn.org/stable/modules/generated/sklearn.svm.OneClassSVM.html

Implication: OC-SVM should stay in the appendix/robustness role unless its
calibration warnings are resolved and explained.

### Wilcoxon Signed-Rank Test

SciPy documents `scipy.stats.wilcoxon` as a paired non-parametric test for
whether paired differences are symmetric about zero. The current v2 package uses
`alternative="two-sided"`, `zero_method="wilcox"`, and `method="exact"`.

Source: https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.wilcoxon.html

Implication: report the two-sided exact p-value unless a prior directional
hypothesis is explicitly documented. Current recomputation gives W=0 and
p=0.00006103515625 for the 112-run lock.

### Android Package-Level Network Attribution

Android's `VpnService` API creates a virtual network interface and can route
traffic through that interface. PCAPdroid-style app-filtered capture is therefore
best described as package-filtered VPN capture, not kernel-level per-process
ground truth.

Sources:
- https://developer.android.com/reference/android/net/VpnService
- https://developer.android.com/develop/connectivity/vpn

Implication: the paper should qualify dynamic traffic as package-filtered
capture produced by the capture tool/VPN model. It should not overclaim perfect
network attribution beyond the capture contract.
